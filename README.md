## 👤 About Me

I work at the intersection of **enterprise computing, applied AI, and open-source research** — building tools that make IBM Z mainframe systems understandable to modern engineering workflows, rather than treating them as legacy to be discarded. I'm an IBM Champion (2025 & 2026), an IBM Z Student Ambassador at the Superstar tier, and an Open Mainframe Project mentee under the Linux Foundation, researching AI-assisted mainframe modernization.

Alongside that, I publish applied ML research — from gradient-boosting ensembles for early medical prediction to reinforcement learning for ICU treatment policy — and build production-shaped software rather than proof-of-concept scripts: typed, tested, and documented. I'm completing my B.Tech in Computer Science at VIT Chennai (2027), and actively preparing for a mainframe engineering internship starting January 2027.

## 🧭 Engineering Philosophy

| **Understand before you automate**       | Deterministic analysis first, generative AI second. You can't safely modernize a system you haven't actually parsed.           |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Legacy is under-tooled, not obsolete** | Mainframes run the world's banking, healthcare, and aviation systems. The gap isn't the platform — it's the tooling around it. |
| **Research should compile**              | A paper or whitepaper is a starting point. If it doesn't map to a working artifact eventually, it isn't finished.              |
| **Modular over monolithic**              | Small, composable, independently testable systems — over black-box, do-everything ones.                                        |
| **Open source is the credential**        | A public repo with tests and commits is worth more than a claim. Show the work.                                                |

### 🩺 KubeMedic

[![Repo](https://img.shields.io/badge/GitHub-View%20Repo-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Edith-Stark06/Kubemedic) [![Python](https://img.shields.io/badge/-Python%203.12%20%7C%203.13-3776AB?style=flat-square&logo=python&logoColor=white)](https://github.com/Edith-Stark06/Kubemedic) [![Kubernetes](https://img.shields.io/badge/-Kubernetes-326CE5?style=flat-square&logo=kubernetes&logoColor=white)](https://github.com/Edith-Stark06/Kubemedic) [![Tests](https://img.shields.io/badge/tests-470%20passing-2ea44f?style=flat-square)](https://github.com/Edith-Stark06/Kubemedic) [![MIT](https://img.shields.io/badge/-MIT%20License-blue?style=flat-square)](https://github.com/Edith-Stark06/Kubemedic)

**Evidence-driven Kubernetes incident response, with a human in the loop.** KubeMedic watches a workload, collects evidence through a read-only MCP server, uses an LLM reasoning engine (IBM Bob, watsonx, Claude, or Gemini — pluggable) to correlate symptoms into one incident and propose an impact-aware remediation, **pauses for a human decision**, executes only an allowlisted action after approval, and independently re-verifies that the service actually recovered on two signals before calling it resolved.

Four rules are enforced in code, not just documented: never fabricate evidence, separate fact from inference from recommendation, never claim success without independent re-verification, and never execute anything a model composed — every mutation is a named, allowlisted operation gated behind a recorded human approval. 470 tests pass with no cluster required; a hash-chained audit trail makes every incident record tamper-evident. Validated against a live IBM Bob run and a live Kubernetes cluster, with executed evidence checked into the repo.

### 🛡️ ATLAS — Adaptive Trust & Lifecycle Assurance System

[![Repo](https://img.shields.io/badge/GitHub-View%20Repo-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Edith-Stark06/ATLAS) [![Next.js](https://img.shields.io/badge/-Next.js%2016-000000?style=flat-square&logo=nextdotjs&logoColor=white)](https://github.com/Edith-Stark06/ATLAS) [![FastAPI](https://img.shields.io/badge/-FastAPI-009688?style=flat-square&logo=fastapi&logoColor=white)](https://github.com/Edith-Stark06/ATLAS) [![PostgreSQL](https://img.shields.io/badge/-PostgreSQL-4169E1?style=flat-square&logo=postgresql&logoColor=white)](https://github.com/Edith-Stark06/ATLAS) [![MIT](https://img.shields.io/badge/-MIT%20License-blue?style=flat-square)](https://github.com/Edith-Stark06/ATLAS)

A governance layer that decides whether autonomous financial agents can be trusted **before** they act — not "is this agent authorized?" but "should this agent be trusted, right now, under these circumstances?" Every action passes through Trust Engine → Policy Brain → Simulation Engine → a hash-chained Governance Ledger before it executes.

All 13 planned build phases are shipped: a trained ML trust engine (logistic regression, isolation forest, and gradient-boosted classifiers, each benchmarked against its heuristic predecessor), versioned rules-as-data in the Policy Brain, a pre-execution Simulation Engine, an Explain AI layer with verified counterfactuals, cohort-based Agent Benchmarking, and Capacity Planning that reports the actual binding constraint on scaling — not just a headline number. A fourth risk model is trained on 284,807 real anonymized European cardholder transactions (Worldline / ULB), separate from the synthetic-trained governance models.

### 🧠 Engineering Knowledge System — Portfolio

[![Repo](https://img.shields.io/badge/GitHub-View%20Repo-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/Edith-Stark06/portfolio) [![Next.js](https://img.shields.io/badge/-Next.js%2016-000000?style=flat-square&logo=nextdotjs&logoColor=white)](https://github.com/Edith-Stark06/portfolio) [![React](https://img.shields.io/badge/-React%2019-61DAFB?style=flat-square&logo=react&logoColor=black)](https://github.com/Edith-Stark06/portfolio) [![TypeScript](https://img.shields.io/badge/-TypeScript%20(strict)-3178C6?style=flat-square&logo=typescript&logoColor=white)](https://github.com/Edith-Stark06/portfolio) [![Tailwind](https://img.shields.io/badge/-Tailwind%20v4-06B6D4?style=flat-square&logo=tailwindcss&logoColor=white)](https://github.com/Edith-Stark06/portfolio)

Not a static portfolio page — an **interactive engineering knowledge system** where every route, command, and search record is derived from a single typed data layer. Next.js 16 App Router with `output: "export"` (17/17 static routes, zero runtime backend), React 19, strict TypeScript, Tailwind v4 with tokens defined in `@theme`, GSAP + ScrollTrigger, Lenis smooth scroll, and a custom WebGL shader background.

Three ideas make it more than a site:

- **Engineering evidence model** — every metric carries a conservative status (`VERIFIED` / `PROJECT-REPORTED` / `RESEARCH-REPORTED` / `UNAVAILABLE`) and resolves to the exact project, publication, or research record backing it. Nothing is fabricated, and unsupported claims render as *unavailable* rather than being filled in.
- **Knowledge graph** (`/knowledge`) — pure SVG, **no graph library**: a deterministic seeded force-directed layout runs a fixed number of iterations and stops. Zoom, pan, node selection, URL-persisted state, full keyboard navigation, and a semantic index as the accessible fallback.
- **Technical depth switch** — each case study renders at `?depth=executive|engineering|research`, resolved server-side from one source of truth; a depth with no supporting material is disabled, never invented.

Plus a `Ctrl+K` command palette indexing every route, project, and publication; a media pipeline validated at build time; and accessibility carried through the whole surface — skip links, focus traps, `prefers-reduced-motion` across GSAP/Lenis/WebGL/CSS.
